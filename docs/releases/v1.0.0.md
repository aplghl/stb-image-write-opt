# stb-image-write-opt v1.0.0

**A byte-identical, drop-in performance release of `stb_image_write.h`.**

Replace your `stb_image_write.h` (or link the prebuilt static library) and your
PNG/JPEG encoding gets dramatically faster, with **exactly the same output
bytes**. No source changes, no build-system changes, no new dependencies, no
runtime CPU checks.

- **Upstream:** `nothings/stb` @ `2c980bb`, `stb_image_write.h` v1.16
- **License:** MIT OR Unlicense (same as upstream)
- **Scope:** the encode/write side only

---

## Highlights

- **+62.7% geomean** across a mixed PNG/JPEG/BMP/TGA/HDR encode suite vs stock
  upstream compiled at `-O2`, using a held-out PGO profile.
- **PNG encode 1.62–2.15×**, **JPEG encode 1.63–2.04×**.
- **~3.4× on the isolated DEFLATE kernel** — the match-length scan that
  dominated PNG encoding.
- **Byte-identical output.** Every optimized path reproduces upstream bytes
  exactly; ~9,650 differential checks across all formats and parameters pass.
- **Zero-cost integration.** Baseline SSE2 only (no AVX2 requirement, no CPUID
  dispatch); scalar fallback on non-x86 and under `-DSTBIW_NO_SIMD`.

## Results

Measured on an Intel Core i7-14700F (Raptor Lake), WSL2, clang 23.1.2.
Candidate flags `-O3 -march=x86-64-v2 -ffp-contract=off` with **held-out** PGO
(trained on inputs disjoint from the measured rows). Ratios only; run-to-run
variation is a few percent.

| workload | speedup vs upstream `-O2` |
| --- | --- |
| Mixed suite (geomean, 17 rows) | **+62.7%** |
| PNG encode (real + generated) | **1.62–2.15×** |
| JPEG encode | **1.63–2.04×** |
| `stbiw__zlib_countm`, isolated | **3.3×** (1.41 vs 4.6 ns/call) |
| DEFLATE, isolated | **3.4×** (0.43 vs 1.47 ns/byte) |
| Downstream consumer program (links the `.a`) | PNG **1.90×**, JPEG **1.17×** |

BMP/TGA/HDR rows are dominated by the per-byte output callback and are
layout-sensitive; they are deliberately not claimed.

## What changed

Only `src/stb_image_write.h` is modified (+95 lines, additive and guarded). The
public API, structs, ABI and default behavior are unchanged — the exported
symbol set is byte-for-byte identical to upstream (16 symbols).

1. **SSE2 DEFLATE match kernel** (`stbiw__zlib_countm`). The match-length scan
   was a byte-at-a-time loop and ~30% of PNG encode time; it now compares 16
   bytes per iteration with baseline SSE2 and finds the first differing byte via
   `movemask` + `ctz`. SSE2 is part of the x86-64 baseline, so this needs **no
   runtime dispatch and no new dependency**; non-SSE2 targets and
   `-DSTBIW_NO_SIMD` use the original scalar loop.
2. **Precomputed fixed-Huffman tables** (`stbiw__huffcode` / `stbiw__huffbits`)
   replace the per-symbol `stbiw__zlib_bitrev` loop when emitting DEFLATE codes.
3. **Binary-searched length/distance code tables** replace the per-match linear
   scans (identical `j`, far fewer comparisons).

The recommended `-march=x86-64-v2` also lets the compiler auto-vectorize the
scalar float JPEG encoder; `-ffp-contract=off` keeps the result byte-exact.

## Correctness & verification

- **Bit-exact differential:** 9,652 checks over 5 formats × comp 1–4 ×
  quality/filter/stride/RLE/flip toggles, on generated and real images, byte
  identical to the pristine oracle at `-O2`.
- **Sanitizers:** ASan + UBSan clean over 1,004 inputs (matrix + truncations +
  mutations). One pre-existing upstream UB (the JPEG bit-writer shift) is
  documented and scoped out via an ignorelist; the oracle is untouched.
- **Portability:** scalar (`-DSTBIW_NO_SIMD`), `-march=x86-64-v2`,
  `-march=x86-64-v3`, C++, gcc/clang, and cross-builds for
  `aarch64-linux-musl`, `x86_64-windows-gnu`, `aarch64-macos`. All pass.
- **ABI:** exported-symbol set identical to upstream.
- **Non-vacuous:** a deliberately corrupted candidate fails the suite
  (2,284/8,308 divergences), proving the tests actually check output.
- **Oracle integrity:** `sha256(stb_image_write.h) =
  cbd5f0ad7a9cf4468affb36354a1d2338034f2c12473cf1a8e32053cb6914a05`, checked
  in CI.
- **CI:** all jobs green on the tagged commit.

## Installation

### Drop-in header

Replace your `stb_image_write.h` with the one in this release (or in the
tarball). Nothing else changes:

```c
#define STB_IMAGE_WRITE_IMPLEMENTATION
#include "stb_image_write.h"
```

### Prebuilt static library

Each tarball extracts to `<triple>/` and contains `stb_image_write.h` plus the
static library. Include the header **without** `STB_IMAGE_WRITE_IMPLEMENTATION`
and link the library:

```sh
cc app.c -I x86_64-linux-gnu x86_64-linux-gnu/libstb-image-write-opt.a -lm
```

Available assets:

| asset | platform | notes |
| --- | --- | --- |
| `stb-image-write-opt-x86_64-linux-gnu.tar.gz` | Linux x86-64 | glibc; link `-lm` |
| `stb-image-write-opt-x86_64-linux-musl.tar.gz` | Linux x86-64 | musl, static |
| `stb-image-write-opt-aarch64-linux-musl.tar.gz` | Linux ARM64 | musl, static |
| `stb-image-write-opt-x86_64-windows-gnu.tar.gz` | Windows x86-64 | MinGW; library is `stb-image-write-opt.lib` |

Or build from source: `zig build -Doptimize=ReleaseFast`
(`-Dtarget=<triple>` for cross builds) or `PGO=1 scripts/build_opt.sh exact`.

| gcc, clang, `zig cc` | byte-exact |

## Known limitations

- The default build targets `x86-64-v2`; `-march=x86-64-v3` is byte-exact but
  not the default (it is not drop-in on pre-Haswell CPUs). Runtime-dispatched
  AVX2 for the JPEG core remains future work.
- `perf`/AutoFDO/BOLT were unavailable (WSL2, no PMU); callgrind and held-out
  PGO were used instead.
- `STBI_WRITE_NO_STDIO` is not exercised by the portability matrix because
  upstream defines `stbi_write_hdr_to_func` only when stdio is enabled; the
  oracle itself cannot link the harness with that toggle.
